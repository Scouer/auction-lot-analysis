# Площадки: массовый доступ к каталогу, оригиналы фото, вынос данных

Назначение — снять с прогона основную статью расхода. Каталог целиком берётся одним запросом,
изображения качает скрипт, в контекст попадают только производные. Приёмы проверены 27–28.08.2026.

## Правило нулевого транзита

**Сырьё не проходит через контекст.** Полные описания лотов, списки изображений, таблицы компаратов,
сами изображения живут в странице, в файле или на диске. В контекст возвращается только то, что
уже является ответом: счётчики, доли, таблица из десятка строк, вывод по кропу.

Проверка перед каждым действием: «этот вывод можно получить кодом?» Если да — код. Каждый вызов
агента платный, каждый вызов скрипта — нет.

## Invaluable

**Каталог целиком.** Витрина отдаёт лоты через Algolia-прокси. Из открытой страницы каталога:

```
POST /catResults        (same-origin, credentials: include, Content-Type: application/json)
body: {"requests":[{"indexName":"archive_lotNumber_asc_prod","params":{
   "filters":"catalogRef:<REF> AND banned:false",
   "hitsPerPage":1000, "page":0, "attributesToRetrieve":["*"], "query":""}}]}
```

Возвращает `hits[]` с полями `lotNumber, lotTitle, lotDescription, moreText, photoPath, lotRef,
catalogRef, priceResult, estimateLow, estimateHigh, artistName, houseName, houseRef, closed`.
**Полные описания включены** — отдельные страницы лотов для текста не нужны.

- `catalogRef` и `catalogId` берутся из `window.__PRELOADED_STATE__.catalog.catalogInfo`
  (`ref`, `catalogId`) на странице каталога.
- Скан по **всему дому**: заменить фильтр на `houseRef:<REF> AND banned:false`; с `query:"<имя>"` —
  это и есть тест ротации имени (`consignment.md`).
- Тело запроса удобнее не собирать вручную, а перехватить: подменить `XMLHttpRequest.prototype.send`,
  вызвать любую пагинацию, взять пойманное тело и переиспользовать с изменёнными `params`.

**Страница лота открывается по любому слагу:** `/auction-lot/a-<номер>-c-<lotRef в нижнем регистре>`.
Слаг не проверяется. Нужна только для галереи: список изображений вынимается регуляркой
`housePhotos/<Дом>/\d+/\d+/H\d+-L[A-Za-z0-9]+\.jpg`.

**Изображения.** CDN отдаёт напрямую (обычный HTTP-клиент, с `Referer: https://www.invaluable.com/`),
без логина и без бот-защиты:

```
https://image.invaluable.com/housePhotos/<Дом>/<две последние цифры catalogId>/<catalogId>/H<id дома>-L<id файла>.jpg
                                                                                    + суффикс _original.jpg
```

Превью галереи — ровно 1000 px по ширине, оригиналы до 7200 px. **Все лоты одного каталога лежат
в одной папке** — путь зависит от каталога, не от лота. Правило v2.0.1 (обязательная попытка
оригинала по каждому файлу и верификация «строго больше превью») действует без изменений.

**Ограничения окружения.**

| Что | Симптом | Обход |
|---|---|---|
| Обычный HTTP-клиент по `www.invaluable.com` | 202 и 0 байт (бот-защита) | только браузер; CDN картинок при этом доступен напрямую |
| Встроенный браузер с контент-блокировщиком | бандлы `/search/static/dist/*` → `ERR_BLOCKED_BY_CLIENT`, каталог не гидрируется, `fetch` тоже режется | Chrome-сессия пользователя |
| Цены проданных лотов | «Sold: Log in to view» | архив под логином; для скана консигнации цены не нужны, доступны из Algolia-выдачи |

## Вынос данных из браузера на диск

По убыванию надёжности:

1. **Считать в странице, вернуть агрегат.** Всегда предпочтительно; в контекст уходят десятки байт.
2. **Скачивание Blob** — работает и кладёт файл в `~/Downloads`:
   ```js
   const a=document.createElement('a');
   a.href=URL.createObjectURL(new Blob([JSON.stringify(data)],{type:'application/json'}));
   a.download='manifest.json'; document.body.appendChild(a); a.click();
   ```
   **Второй автоматической загрузкой Chrome блокирует** — за один заход выносить один файл.
3. `fetch` на `http://127.0.0.1` из HTTPS-страницы **блокируется** смешанным содержимым —
   локальный приёмник не работает, время не тратить.
4. Возврат больших строк через инструмент — режется по размеру; для сотен строк непригоден.

Расширение браузера может отказаться вернуть результат с пометкой «Cookie/query string data» —
это срабатывает на строках, похожих на URL с query. Обрезать всё после `?` и возвращать
только имена файлов.

## Auction Mobility (Oakridge и др.) — встроенный JSON каталога

Дома на платформе Auction Mobility отдают полный список лотов в JSON прямо на странице каталога:

```
live.<дом>.com/auctions/{row_id}/x?page=N     # слаг любой, 36 лотов на страницу
live.<дом>.com/auctions/past?page=N           # перечень прошедших сессий
```

Поля: `status` (непроданные помечаются `expired`), **`sold_price`**, `estimate_low/high`,
`dimensions`, `condition`. **Это редкий случай, когда молоток отделим от премии:** сумма
`sold_price` по проданным лотам сессии сходится с полем `total_hammer_price` — проверено
на сессии Oakridge 18.09.2023 (163 лота, $841 400). Приём переносится на любой дом этой платформы.

Что не работает: HiBid маскирует цены плейсхолдером `123.45` и отдаёт только открытые лоты;
Bidsquare API отвечает 401; LiveAuctioneers под Incapsula.

## Прочие площадки

Паттерны не проверены — при первом контакте с новой площадкой действовать той же лестницей
(перехват XHR → внутренний API → регулярка по HTML) и **дописать сюда результат**: этот файл
накопительный, каждый разобранный дом делает следующий дешевле.
