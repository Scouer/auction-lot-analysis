# Фаза −1: входной шлюз — полный регламент

Исполняет Директор-оркестратор. Сабагенты до исхода «Разбор» не спавнятся. Цена, эстимейт, старт, счётчик ставок в решения шлюза не входят ни в каком виде.

## Ш0 — отпечаток среды

Первым действием: режим **M / C / 1К**, доступность vault, логинов, браузерной сессии, канала к пользователю, цзыша-конвейера. По каждому недоступному ресурсу — строка матрицы деградации SKILL.md → гриф в шапку. Обходы вне матрицы запрещены.

**Версия плагина (v2.4.2).** Тем же первым действием читается `version` из `.claude-plugin/plugin.json` пакета навыка (корень пакета — на два уровня выше `skills/auction-lot-analysis/`) и сверяется с последним релизом репо `Scouer/auction-lot-analysis` (`git ls-remote --tags https://github.com/Scouer/auction-lot-analysis` или GitHub API `releases/latest`; репо недоступно → «сверка не выполнена», гриф). Пакет отстаёт → **первая строка ответа владельцу**: «плагин устарел vX.Y.Z → vA.B.C, обновить: `claude plugin update antique@scouer`», гриф `плагин устарел vX.Y.Z` в шапку и в YAML-хвост. Прогон на устаревшей версии валидным не считается: его формы при перепрогоне уходят в карантин `research/<среда>-<дата>/`, выводы не наследуются. Версия в шапке и в `skill_version` — прочитанная из файла, не из памяти. (Урок [[2026-09-15-LONDON-844]]: Cowork на 2.0.x подписал «Разбор/Стандарт» при печати V0 — по Ш3 это Запрос.)

## Ш1 — паспорт листинга

Читаются **только структурные поля** (проза описания — в Фазе 1, после Фазы 0):

| Поле | Зачем |
|---|---|
| Дом, юрисдикция | канал, налоговая схема, досье продавца |
| Дата/время сейла + пояс; тайм-аукцион или живой; № лота | дедлайн |
| Заголовок целиком | категория, имя, ступень каталожной лестницы → маршрут и триггер декоративного трека |
| Размеры, материал, вес из спецполей | масштаб px/см, CITES-флаг, вес против размера |
| Число фото; кондишен-репорт есть/нет; поле провенанса есть/нет | вход Ш2, флаги |
| Премия и условия канала | множитель посадочной (парковка) |
| Эстимейт | фиксируется как данные; в исход, ярус и приоритеты не входит |

**Дедлайн.** Считается арифметически (код, не прикидка): ISO 8601 + IANA-зона, вывод в поясе дома и в **Europe/Moscow**. Смещение из risk-profile — только кросс-чек: расхождение больше часа → флаг «пояс профиля устарел» в шапку и отчёт. Для живого аукциона с каталогом на сотни лотов — оценка времени лота по скорости дома (60–120 лотов/час), помечается «оценка».

**Статус торгов.** Витрина площадки — не источник: кэш показывает предаукционный вид с активной кнопкой после закрытия. Подтверждение: архив под логином пользователя ИЛИ вопрос пользователю. Оба канала недоступны → работать по T-времени каталога, гриф `статус: T`, плюс **строка робастности**: что меняется в исходе при гипотезах «торги идут» / «уже закрыты». Максимум заранее не ставится, пока статус не подтверждён.

## Ш2 — фото

- **N** — уникальные снимки: дубликаты, кропы одного кадра, промо-коллажи, логотипы не считаются.
- **Покрытие** — дробью: закрытые критические зоны / все критические зоны категории по `zones.md` («6/8»). Знаменатель — только из zones.md; самодельные списки запрещены (нефальсифицируемость).
- **Разрешение** — пикселей на зону в самом крупном доступном файле, не в превью; «самый крупный доступный» = после обязательной попытки оригинала по каждому файлу (лестница «Механики максимального разрешения» SKILL.md: паттерн CDN `_original` → клик по фото + zoom-in → верификация «скачанное строго больше превью»). Пороги — zones.md. Серая зона 300–800 px = «читаемо на V2»: проходимо, потолок понижен, гриф в шапку. Для иероглифики — порог на знак.

## Ш3 — исход

| Исход | Условие | Действие |
|---|---|---|
| **Разбор** | N ≥ N_min категории (zones.md) **и** закрыты все зоны класса «ценность» **и** покрытие прочих критических ≥ 70% **и** читаемость по порогам | протокол по ярусу и треку |
| **Разбор (неполные данные)** | есть хотя бы один снимок предмета, но условия «Разбор» не выполнены (зона ценности не снята / не читается, покрытие < 70 %) | полный протокол по ярусу и треку на имеющемся; гриф `данные неполны: …`; ставка по нижнему сценарию (as-is) |
| **Отказ** | торги закрыты; N = 0 снимков предмета; лот снят | форма «Отказ», ≤7 строк, reopen, строка в индекс |

Зоны класса «ценность» — несущие атрибуцию/стоимость: клеймо, подпись, печать, надпись, дата (список по категории — zones.md). Их отсутствие в съёмке — само по себе наблюдение о листинге → досье продавца.

**Ветка «Разбор (неполные данные)» (правило владельца 2026-09-09).** Запросы дому и продавцу не делаются и не предлагаются: площадочные продавцы не отвечают, осмотр вживую невозможен, листинг — это все данные лота. Протокол выполняется целиком на том, что есть, с максимумом выжимки (нативные кропы, апскейл для просмотра, второй читатель, обратный поиск, база сверки). Каждая незакрытая зона — строка реестра открытых зон: зона · факт (px / нет снимка) · какой вывод на ней висит · как понижен потолок. Реестр — в шапку грифом `данные неполны: …` и в раздел «Насколько можно верить» отчёта пользователю. Потолок вердикта по незакрытой зоне — «не опровергнуто / не подтверждено»; оптимистичный сценарий ставки запрещён (правило as-is). Отсутствие снимка зоны ценности — наблюдение о листинге в досье продавца. Окна времени остаются только для цейтнота (<2 ч → усечённый протокол).

**Ветка «Отказ».** Форма ≤7 строк (report-form.md): причина конкретным несоблюдённым условием, факт (N, покрытие, px), reopen-условие («появятся фото дна и клейма ≥800 px», «лот перевыставят»), строка в `_index.csv` (ценовые поля пустые — легально), наблюдение о листинге. Протокол не запускается, вердиктов нет.

## Ш4 — скан консигнации (перед Фазой 0)

Проверить триггеры `consignment.md`: провенанс ссылается на диапазон лотов · назван именем
коллекционера без документов · сейл тематический под одну коллекцию · в сейле ≥3 лота одного
громкого имени · «документы коллекции» проданы отдельными лотами · дом уже помечен в досье.

Сработал хотя бы один → **скан консигнации обязателен и выполняется до дорогого разбора лота**.
Скан дешёвый: каталог целиком одним запросом (`platforms.md`), разбор кодом, в контекст —
агрегаты. Останавливаться, как только исход ясен.

Сначала проверить, не просканирован ли сейл уже: `Projects/antique/sales/<дата>-<ДОМ>-<REF>/`.
Скан делается **один раз на сейл** и переиспользуется всеми его лотами.

В шапку: `консигнация: просканирована (N лотов) · признак серийный / единичный / не проверялся`.
Результат скана меняет вес провенансной строки в Фазе 2 и может перевести её в §14 красные флаги,
но исход шлюза (Разбор / Разбор (неполные данные) / Отказ) не меняет: шлюз решается только данными и временем.

## Маршрутизация (после исхода «Разбор»)

Порядок проверки: цзыша → декоративный триггер → живопись/имя → сужение → общий.

1. **Цзыша** — по SKILL.md (лестница доступности конвейера).
2. **Декоративный трек** — ступень заголовка ≤ «follower of / manner of / after / style of / bears signature / school of» и продавец нигде не утверждает авторства.
3. **Живопись с заявленным именем** — модуль painting; китайская/японская — общая воронка + Д1 + печати (identification.md 2b).
4. **Режим сужения** — атрибуции нет или «wohl / probably / неопределённое».
5. Остальное — общая воронка по категории.

**Ярус** — по таблице SKILL.md. Обязательная проверка: имя в fake-списке base-rates.md → минимум Стандарт. Ярус и трек пишутся в шапку; молчаливое изменение запрещено.
